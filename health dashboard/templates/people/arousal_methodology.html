How a day's number is produced

  1. The readings stored for {{ person.display_name }} on one local day ({{ person.timezone }}) are read. They came from uploaded files and nothing is fetched from anywhere.
  2. They are cut into {{ window_seconds }}-second windows, stepping every {{ step_seconds }} seconds — the same geometry the model was trained on. A window holding fewer than {{ min_samples }} readings is dropped rather than described by statistics computed from almost nothing. A day is only scored if at least {{ min_windows }} windows remain.
  3. Five features are computed per window: mean, standard deviation, minimum, maximum and slope of the heart rate.
  4. The model labels each window, and the page reports the label that won the most windows.
  5. Before that label is shown, each feature is compared against the range seen in training, and the comparison is displayed with it.
  6. Nothing is learned from the day: the model was fitted on WESAD only and the uploaded data is only scored.

Why there is no accuracy figure for uploaded data

There is no ground truth. Nobody recorded which minutes of these days were stressful, so there is nothing to score the predictions against. The cross-validated numbers above describe how the model performs on the laboratory dataset it was trained on — they are not a claim about how it performs on {{ person.display_name }}.
